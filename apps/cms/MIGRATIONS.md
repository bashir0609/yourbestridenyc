# PostgreSQL migration policy

## Current state

There is intentionally **no fabricated initial SQL migration** and no placeholder `up`/`down` function. The schema is defined by the collections, globals, auth/version tables, and Payload plugins in `src/payload.config.ts`. `src/migrations/` is the adapter's migration directory. This package is **not ready to point at an empty production database until a real initial migration has been generated, reviewed, and applied**.

`DATABASE_PUSH` defaults to false and is rejected when true under `NODE_ENV=production`. It may be enabled only for disposable development databases. Do not mix development schema push with a production migration history, and do not mark a migration applied just because a local pushed schema happens to match.

## Initial migration (main/release owner)

Run commands from `apps/cms` after a complete workspace-root `pnpm install --frozen-lockfile` and valid environment setup (`DATABASE_URI` for PostgreSQL; see [R2 deployment guide](DEPLOYMENT.md)):

1. Provision a disposable PostgreSQL database of the same major version/extensions as production. Set `DATABASE_PUSH=false`. Keep production credentials out of development shell history.
2. Run `pnpm migrate:create initial`. Payload/Drizzle generates the actual migration and schema snapshot from the configured model. Answer any rename/destructive-change prompts deliberately.
3. Review **all generated files**, including the migration registry (`src/migrations/index.ts`) if generated. Expect collection tables, enum values, relationship/array tables, unique/indexed slugs, editorial version tables, globals, and Payload auth/internal tables. Check identifier lengths, constraints, relationship foreign keys, data-loss operations, and down behavior. Do not manually invent missing Payload internals.
4. On a separate pristine test database, run `pnpm migrate`, then `pnpm migrate:status`. Confirm a clean application start and test reads/writes/publication, auth/bootstrap, relations, and private intake permissions.
5. On a disposable database only, test rollback with `pnpm exec payload migrate:down` and reapply. Some changes are inherently destructive: document restoration or a forward-fix strategy instead of promising a lossless rollback.
6. Have the repository owner review and commit the generated migration/snapshot/registry together with the schema changes. No migrations or commits have been generated by this implementation task.

## Subsequent schema changes

Generate migrations after each intentional schema change using `pnpm migrate:create descriptive_name`. Review generated diffs; distinguish renames from drop/create operations. Test upgrade from a production-like backup, not only an empty database. Use expand/contract changes when old/new app versions will run together. Keep type generation (owned by the main workspace) separate from schema migration and component import-map generation.

## Release sequence

1. Verify the exact release lockfile and run tests/build in CI. Deploy only reviewed migration artifacts.
2. Back up the database and coordinate public-media backups. Verify restoration procedures before destructive changes.
3. Quiesce writes when needed. Run `pnpm migrate:status` and `pnpm migrate` as **one controlled release job** with appropriate DDL privileges. Do not run schema changes on every web replica/startup.
4. Verify status, constraints, application health, role access, and storage. Then deploy/enable the new application version according to the migration's compatibility plan.
5. Roll back code only if the database remains backward-compatible. Otherwise use a reviewed forward fix or restore the backup under the incident plan. Never use `migrate:reset`, `migrate:fresh`, or schema push on production.

The runtime database role should have only the privileges it needs; use a separately controlled migration role when feasible. Secrets, CA certificates, backups, maintenance windows, rollout orchestration, and the actual generated migration files are deployment-owner responsibilities, not supplied infrastructure.
